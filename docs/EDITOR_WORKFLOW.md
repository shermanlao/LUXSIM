# Editor workflow

The project editor is **`BuildingEditor`** (`ProjectSceneV2`). Legacy v1 `ProjectEditor` lives under `src/components/editor/_legacy/` for reference only.

On project routes, the editor uses a **dark CAD shell** (`cad-editor`): full-bleed layout (footer hidden), top file bar + **workflow ribbon** (Construction → Light → Calculation → Documentation), left building tree + tools, centre viewport with view tabs, right properties/library/export by mode, and a bottom **results strip** (Ēm, maintained Ēm, Uo, UGR, LPD, EN assist).

`BuildingEditor` and app chrome use the **full browser width** — no `max-w-7xl` cap — so the 3D viewport and side panels expand with the window.

The editor does not silently autosave. A **save reminder** appears after **15 minutes** of unsaved persistable edits by default (configurable per account: Off / 1 / 5 / 15 minutes — click your email in the header). **Save** on the dialog or the toolbar writes name / scene / results. The editor does not flush on tab hide or after a successful calc. Selecting a room or switching view / tool does not start a save. Only fields that actually changed are PATCHed. See [AUTOSAVE.md](./AUTOSAVE.md). View tab and last 3D orbit (`ui.camera3d`) are included when a real save runs. **Undo** is Ctrl+Z (Ctrl+X also undoes in the plan/3D view; Cut still works in text fields); redo is Ctrl+Y or Ctrl+Shift+Z.

2D drag/drop uses `getScreenCTM()` (`svg-coords.ts`) so fixture picks stay under the cursor when the viewport is wider than the SVG viewBox (letterboxing).

1. **New project** — empty GF storey, no rooms. **Copy storey** in Building copies the current storey into a new storey named Copy of {name}, placed immediately above the source (source elevation + source storey height, or the next free slot if that elevation is taken). Rooms and luminaires are copied with new ids; underlays and calculation results are not. The new storey is then selected.
2. **Import plan** (optional) — PNG/JPG/PDF/DXF/IFC. **PDF** is rasterized server-side (pdf.js) to a PNG underlay for Top/Bottom/3D; multi-page PDFs have a **page picker** in Construction. Raster plans keep aspect ratio. **Calibrate** (two-point + real length in m) sets `metersPerUnit` — unchanged from image plans.
3. **Calibrate** — tool → set real distance → click two points (uniform scale; does not distort the plan). When the underlay is a parsed DXF, those clicks snap to endpoints, midpoints, and the nearest point on a segment within 8 CSS pixels at the current zoom, same as other official Top/Bottom picks. Image/PDF underlays have no raster snap. A DWG import is converted and then works like a DXF underlay.
4. **Draw rooms** — Draw room on Top or Bottom: left-click corners, type mm to lock the next length (polar circle), click the start point to close. With a DXF underlay, those corner picks (and Line / Circle / Polygon array picks, plus fixture drops) use the same official object snap. **Create rooms from DXF** makes rooms from closed polylines, from simple closed loops of connected lines, and from each minimal room face in a T-junction or shared-wall network on the current storey (official new-room defaults; scale follows the current Calibrate scale). Official rooms are simple polygons without holes: if one room lies fully inside another with no connecting wall, only the inner room is kept. A DWG import is converted and then works like a DXF underlay. CIRCLE, ARC, ELLIPSE, SPLINE, old POLYLINE, and LWPOLYLINE bulges are also traced (curves as polygons). A non-mesh 3D POLYLINE is traced in plan (Z is ignored). Paperspace entities (group 67 = 1) are not displayed, snapped, bounded, or used to create rooms. Polygon-mesh and polyface-mesh POLYLINE entities are skipped. For a quick rectangle, enter L×W (mm) and create at `(0, 0)` — this form does not pick on the plan. After creation, select the room and drag a corner handle to stretch that vertex, or drag a mid-edge handle to insert a new corner and place it in the same drag (DXF snap applies; invalid inserts or stretches revert to the pre-insert or pre-drag polygon). Hover or click a corner handle, then press Delete or Backspace to remove that vertex; invalid deletes are refused and the room is left unchanged. Draw-room Backspace is unchanged. Rooms and storeys are not translated by dragging the room fill. **Union rooms** merges two overlapping or edge-adjacent rooms on the current storey into the first room (Esc cancels the pick). **Subtract rooms** cuts the first room by a second room on the same storey; the first room keeps its properties, the cutter stays in place, and a result that would be empty, split into islands, or contain a hole is refused (Esc cancels the pick). **Intersect rooms** keeps the overlapping area as the first room and removes the second; the rooms must overlap in area, and a result that would be empty, split into islands, or contain a hole is refused (Esc cancels the pick). **XOR rooms** keeps the exclusive parts as the first room and removes the second; a bite that shares the outer boundary can succeed, and a result that would be empty, split into islands (typical when both rooms have a remainder), or contain a hole is refused (Esc cancels the pick). **Align rooms** translates a second room on the current storey so a chosen edge or centre (Left, Right, Top, Bottom, H centre, or V centre) of its bounding box lines up with the first (reference) room; the reference stays put, both rooms are kept, and fixtures of the moved room follow (Esc cancels the pick). **Distribute rooms** spaces three or more rooms on the current storey with equal gaps between bounding boxes along Horizontal or Vertical; the first and last rooms along that axis stay put, interiors move, and fixtures of a moved room follow (Enter applies; Esc cancels the pick). **Fillet corner** rounds one selected corner of a room on the current storey (radius in millimetres; click a corner handle; a mid-edge handle is not a target; Esc cancels the pick). **Fillet all corners** fillets every remaining sharp corner of one room on the current storey in one command, using the same radius field (if a room is already selected it applies immediately; otherwise click the room; mid-edge handles are not targets; Esc cancels the pick). Move a single fixture with Select / move. A snap marker does not start a room, storey, or fixture drag. See [ROOM_DRAW.md](./ROOM_DRAW.md).
5. **Upload IES/LDT** — appears in fixture list only.
6. **Drag** fixture onto a room (Top / Front / Side / 3D), or use **Light → Arrange · array / 排列**: rectangular / line / circular / polygon (room outline or a custom path) arrays, or **By target Ēm / 目標照度** (F1.2 — lumen method estimate `n ≈ ceil((Ēm×A)/(Φ×η×MF))`, square-ish grid, spacing from room bounds − wall offset; Preview ghosts on Top; Apply via `writeFixtureInstances`; status reminds **Estimate only — run Calc**). Optional **Calc after place / 放置後計算** uses F2.6 post-place calc.
7. **Code map** (Light mode): define schedule codes → luminaire rules on the project scene (`fixtureCodeMap` JSON, autosaved). Optional CSV `code,luminaireId`. Test lookup shows mapped / ambiguous / unmapped — pipelines must not guess.
7b. **Import schedule / 匯入 schedule** (F3.1): CSV `code,x,y[,z,rotationDeg]` in **metres** on active storey → preview table (map status, accept/reject) → **Commit schedule** writes only **accepted + mapped + inside room** rows via `writeFixtureInstances` (optional F2.6 calc). Accepted but unmapped/ambiguous **blocks** commit; points outside rooms skipped with count. No OCR.
8. **Detect from plan / 從圖則偵測** (Light): local OCR → confirm table → **Commit accepted** writes fixtures (F2.4). Optional **Calc after commit / 提交後計算** and **Arrange · Calc after place** share **`runPostPlaceCalcForRooms`** (same client solver as **Calc room/all**): updates `ResultsV2` for the bottom **Ēm / Uo / UGR / LPD / EN assist** strip and false-colour / isoline views; missing IES/LDT lists luminaire names; calc errors do not remove placed instances (F2.6).
9. **Calculate** active room or all rooms (client-side). Optional **Calc after place** when applying an array (or enable before drag-drop).
10. **Documentation** mode — full PDF report, `.lxm` (includes the plan underlays the scene uses), or DIALux verification zip.

**Persistence:** fixture code map rules live in **`ProjectSceneV2.fixtureCodeMap`** (project `sceneJson`), not a separate DB table — they travel with `.lxm` export and autosave. Official **Save .lxm** also embeds the plan underlays the scene uses, so **Open .lxm** can restore them in a new workspace. Each rule has an `id` used as the table row key; load fills one in when an older row omitted it.
